## 3. 사소한 게임 업데이트가 일어나면 지금 어떻게 되나

| 변하는 것 | 가능성 | 지금의 결과 | 사용자 눈에 |
| --- | --- | --- | --- |
| 빌드 식별자 (**패치마다 바뀜**) | 매우 높음 | 체력 기반 사망 감지가 옛 카메라 방식으로 후퇴, 헬밤 카운트다운 꺼짐 | 조용히 나빠짐, 로그 한 줄뿐 |
| 유닛 경로 변경·삭제 | 중간 | 해당 마커만 조용히 사라짐 | 조용함 |
| 새 유닛 추가 | 중간 | 표시 안 됨 | 조용함 |
| 아바타 경로 변경 | 낮음 | **모드 전체가 아무것도 안 그림** | 원인 불명, 로그에도 없음 |
| 네트워크 필드 변경 | 낮음 | 스키마 검사로 안전하게 멈춤 | 데스 마크 없음 |
| 노드 이름 변경 | 낮음 | 기준점으로 대체, 위치 약간 어긋남 | 작음 |
| 패치·텍스처 형식 변경 | 드묾 | 모든 모드가 함께 깨짐, Chef 업데이트 필요 | 큼, 우리만의 문제는 아님 |
| Chef 규칙 변경 | 중간 | **실제로 일어남** (1번 문제) | 조용히 기능 상실 |
| 패치 후 네이티브 호출 크래시 | 낮음 | Keep-On-Crash 때문에 모드가 자동으로 꺼지지 않음 | 반복 크래시 가능 |

가장 큰 위험은 **크게 깨지는 것보다 패치마다 조용히 나빠지는 것**입니다. 빌드 허용 목록이 그 원인입니다.
목록에 있는 두 빌드에서 네트워크 타입 이름(`un6y1d`, `vvhx8ga`)이 같았으므로, 작은 패치에서는 유지될 가능성이 높습니다.

## 4. 제안 (승인 대기, 아직 구현 안 함)

우선순위 순서입니다.

**A. 빌드 허용 목록을 스키마 검사로 교체 (추천, 효과 가장 큼)**
`local_player.lua`의 `BUILDS` 대신, 이미 있는 `Network.object_info` 필드 검사를 판정 기준으로 씁니다. 첫 임무에서 검사가
실패하면 옛 카메라 방식으로 후퇴합니다. 추가 안전장치로, 처음 읽은 네트워크 위치가 실제 헬다이버와 1m 안에서 일치할 때만
믿습니다. 위험은 낮습니다. 필드를 읽기 전에 이미 타입과 존재를 검사하고, 호출은 Chef 크래시 가드를 거칩니다.

**B. 헬밤 카운트다운을 모르는 빌드에서도 조건부로 허용 (추천)**
모르는 빌드에서는 `ARMED`를 쓰지 않고, **`1 → 0` 전환을 직접 본 경우에만** 카운트다운을 띄웁니다. 그래프 번호가 바뀌어도
결과는 잘못된 경고가 아니라 카운트다운 없음에 그칩니다. 애니메이션 읽기는 과거 크래시 이력이 있는 호출이라 소유자 판단이
필요합니다. 더 보수적인 대안은 허용 목록을 유지하고 F의 점검 도구로 한 줄씩 추가하는 것입니다.

**C. `HD2-Keep-On-Crash` 제거 (추천)**
Chef 1.3부터 이 표시 없이도 튕긴 호출만 건너뛰고 모드는 켜져 있습니다. 표시가 없으면 4회 연속 실패 시 모드를 끄고, 건너뛴
호출을 게임이나 로더 업데이트 뒤 다시 시도합니다. 표시가 있으면 둘 다 하지 않습니다. 문서도 "시험자용"으로 안내합니다.
2.4.0 때 넣은 이유(한 번 튕기면 영구 정지)는 더 이상 없습니다. 요구 버전이 이미 1.4.0입니다.

**D. Chef 공식 진입점으로 이동**
`_G.update` 교체는 "옛 로더 방식"입니다. 지금은 작동하지만 반환 표에 함수가 하나라도 생기면 조용히 멈춥니다. 공식 형식은
`update`와 `shutdown`이 든 표를 반환하는 것입니다. 또한 `Application.can_get`, `Window.show_cursor`를 직접 부르는 대신
`chef.call`을 쓰면 크래시 가드가 적용됩니다.

**E. 자가 진단 한 줄**
임무 시작 30초 뒤 로그에 한 줄을 남깁니다: 헬다이버 수, 찾은 대상 수, 식별 방식(network/legacy), 텍스처 정상 여부. 3장의 "원인
불명" 사례를 제보 하나로 판별할 수 있게 됩니다.

**F. 패치 날 점검 도구 `tools/check_game_update.py`**
게임이 패치되면 1분 안에 확인합니다: 빌드 식별자, 대상 87개 존재, 새 후보 유닛, 패치 헤더, 네트워크 스키마, 헬밤 그래프.
이번 검수에서 앞의 네 가지를 손으로 해 봤고 약 40초 걸렸습니다. 사용자가 제보하기 전에 먼저 알 수 있게 됩니다.

## 5. 표시 대상 후보 (소유자 판단)

현재 게임에 있지만 표에 없는 유닛입니다. 실제 등장 여부는 게임에서 확인이 필요합니다.

- `discoverables/ammo_support_discoverable_box_01`: 지원무기 탄약 상자로 보임 (패키지 3곳)
- `obj_illuminate/il_stratagem_scrambler/il_scrambler_battery`, `il_destroy_weather_device/il_weather_device_battery`: 운반 배터리
- `obj_common/raise_flag/carry_flag_01`: 운반 깃발
- 샘플별 `*_pickup_*` 15종: 줍는 순간 손에 쥐는 유닛일 가능성이 높아 제외를 권합니다.
